# ASIT lesson planner with pre-registered evidence (v0.2.10)

Choose one communicative `can-do` outcome grounded in learner request and verified performance. If requested outside-plan practice, honor it without replacing the plan. Use `asit-exercises` for native UI, `asit-media` for real listening and `asit-assessment` after a real answer. **A completed assessed lesson hands off automatically to a new fully rendered lesson under [post-submit continuation](../asit-assessment/references/auto-continuation.md), unless the learner explicitly pauses.** Do not substitute a next-topic announcement or a “start” link for the actual follow-on lesson.

## Mandatory no-leak / no-copy audit with immediate correctness feedback

Before designing task prompts, recording Activities or rendering full lessons, load [answer integrity](references/answer-integrity.md). Audit the **whole rendered lesson**, not only each prompt: look for exact or paraphrasable answers in story text, option labels, image text, captions/alt, examples, prior guided tasks, placeholders, vocabulary and client feedback. **The learner explicitly requires immediate Correct / Incorrect (Try again) UI feedback on deterministic choices, cloze and completed ordering after the first action. This remains enabled; do not wait for final Submit.** The no-hints preference means no advance answers and no revealing/directional clue after an incorrect attempt; it does NOT suppress a correctness verdict. Use brief after-correct reasoning only if it cannot solve another unfinished task. Natural/free writing or plausible synonyms require semantic teacher assessment after Submit, never naive string matching. Independent transfer must not be answerable by retyping a supplied sentence; change the situation or information demand. Do not promise technical clipboard/paste prevention.

## Before rendering a graded lesson: Save Gate preflight

1. If verified prior storage state is known/discoverable using authorized Drive tools, load only bounded `asit-progress` state: effective recording consent, seven Config values, exact nine sheet headers, current revision, lesson preference, active plan, due reviews and few relevant attempts. Do not hydrate the entire history. In ordinary chat, no automated Google Drive connection is bundled with ASIT.
2. If consent permits writing and provider/workbook/schema are verified, define **each subtask's** Activity ID, session/lesson/competency ID, real modality, actual operation and trusted rubric **before** presenting the form. Register separate Activities in learner-owned Sheets and read back each exact Activity ID. One composite outer `ASIT_ATTEMPT_V2` is an envelope, **not** a graded Activity spanning modalities. Do not persist keys, user responses or unconsented data elsewhere.
3. Only after all required Activity registrations verify may the displayed lesson be marked `save-ready`. A skipped/failed preflight means **explicitly unsaved**: teach normally, disclose storage unavailability, do not later invent registered tasks or promise automatic saving. Never publish fabricated registration IDs, use DIL runtime `useId()` as a durable Attempt ID or claim guaranteed global uniqueness. Mint stable opaque IDs and validate uniqueness against stored records before writes.
4. If consent is disabled, no writes; create normal unsaved lesson without extra Drive calls. Existing `summary_only` consent is valid; do not request it each time.
5. **For automatic follow-ons,** check whether this predecessor Attempt/Session already produced a registered/rendered successor. Reuse a verified existing successor on replay rather than registering duplicate next Activities. Previous lesson sync receipt does not establish next lesson's preflight.

## Structured planned lesson

Default: seven minutes and four related tasks **unless** current request or verified learner Config specifies a different count/budget (e.g. five). Current request overrides stored preference. One response contains: topic, real situation and outcome; one/two rules or comprehension strategy; coherent practice form; vocabulary 3–6 chunks last; **one real final Submit**. Prefer three different operations (notice/recognize → reason/repair → construct → independent contextual communication) and one visually meaningful scene when reliable. On deterministic items show **provisional immediate Correct / Incorrect (Try again)** only after a response, with selectable retries and first-attempt metadata where possible; do not pre-reveal keys, give spoiler hints on wrong choices, or leak answers to later independent tasks. Free writing and uncertain aliases are assessed after Submit.

**Required for EVERY full planned lesson:** load and apply [visual-first lesson standard](references/visual-lesson-standard.md) **before** choosing Activities, selecting images or rendering UI. For topics naturally suited to images and with genuine image support, default includes 16:9 thematic cover and at least two image-dependent graded interactions with distinct operations in a 4–5-task lesson; image-labelled words, picture choice and sentence cards take precedence over repeat translation prompts. Include a short Brilliant-style predict/manipulate/explain cycle where appropriate; Duolingo-like low-friction retries and Skyeng-like contextual transfer without copying either product. Honest text-only fallback for unavailability or nonvisual content. Check task mix immediately before rendering; do not add filler media.

For each task specify trusted source rubric, accepted variants, required flag, modality/operation and help policy. Missing required answers block ordinary completion or explicitly `not_assessed`. With consented storage, each graded subtask separately registered and later independently assessed/saved even though one form submits them. Submit envelope carries stable parent ID + task ID → answer mapping, first/revision metadata untrusted. No fake drag, Play, mic or image-hotspot controls.

## Adaptive teaching and end-of-lesson checks

Use earlier useful pattern briefly, change cognitive operation after repeated independent error, scaffold progressively and fade support; choice success does not prove transfer. Close repeated remediation after two focused cycles unless user asks for more. **Close the targeted remediation cycle, not the learning program: hand off to a different planned can-do and render the next full lesson in the same post-submit turn.** Independent final message should solve a new realistic situation. Review interval is heuristic. Typed practice does not prove listening/speaking.

Reject near-duplicate translation tasks, purely decorative images as evidence, link-only listening, inert buttons, fabricated telemetry, exposed keys, wrong learner-preferred count, completion before a final Submit, and a graded lesson that ends with only a suggestion to start another one. Confirm Save Gate status is truthful; register BEFORE displaying the next lesson when enabled, not retrospectively. Additional details: [experience planner](references/experience-planner.md), [lesson rules](references/lesson-rules.md), [post-submit continuation](../asit-assessment/references/auto-continuation.md).

When making ranked or adaptive decisions, lazily load [selection invariants](references/selection-invariants.md) and [optional can-do prompts](references/can-do-starters.md) only if needed; these port the useful reference algorithms without executing JavaScript.
