# ASIT lesson style and quality gate (v0.3.4)

Apply **before writing Activities to Google Sheets and before rendering every complete lesson**. This is a model-executed checklist, not an executable runtime or guarantee of media playback.

## Stronger default policy (v0.3.4) — applies before EVERY full lesson

Read [mandatory rich default](rich-default-lesson.md) and the [complete native template](../../asit-exercises/references/complete-native-lesson.md), including on an ordinary "continue". A **user does not have to request games or images**. A successful normal lesson must have functioning interactive UI and a visual scene with a state transition. **If authentic photos are unavailable**, use a **real self-contained SVG diagram**, explicitly labelled symbolic and assessed as `visual_symbols` rather than `image_choice`; do not downgrade all five tasks to prose. *Genuine photographs* are conditional on actual retrieved assets, not on an invented ref. At least one native control must produce a visible learner-caused diagram/assignment state change, and all deterministic inputs must receive after-action feedback. The picture must serve the learner's reasoning, not merely decorate the heading.

## Lesson style — fixed, concise

**Light card layout; one situation and one action per screen; 16:9 scene cover; real object/action pictures directly beside their questions; short instructions; large working controls; instant Correct / Incorrect after deterministic input; one real Submit.** Use 1–2 sentence explanations, never decorative charts, fake animations, or icon-only substitutes called photographs. Russian for short explanations, English for prompts, messages and learner responses. Match accessibility/low-bandwidth or user-directed text-only requests.

## Mandatory asset & learning-evidence gate (October 2026 regression)

1. Load [the media provenance contract](media-provenance.md). Each assessed photograph requires an **exact current-turn source tool result ref** and an inspected asset matching the rubric. A hallucinated `turn...image...` identifier or unverified candidate page is a **hard fail**. Even a real result cannot prove that a user's client rendered it; retain a verified-source vs host-displayed distinction. Rebuild unavailable media tasks **before** the Sheets Activity write with correct nonvisual modality/operation. If learners report a broken image only after presentation, grade visual work `not_assessed`.
2. Distinguish real scene photo, generated image, **SVG diagram/visual symbol**, and proven animation. Source-verified static photo is not motion, and SVG state change is not continuous animation. For games use [stateful game patterns](../../asit-exercises/references/game-patterns.md): real control actions, state change, feedback, meaningful consequences and transfer, not a picture plus five generic choices.
3. The tutor must classify skipped independent writing as **not assessed**. Repeated blank textareas do not show low proficiency, unwillingness, or any other cause. When the learner explicitly says "I skipped deliberately", use [response-format adaptation](../../asit-core/references/format-adaptation.md) and rotate the input pattern. Do not simply move another compulsory textarea up the list. An optional short original question can assess writing when actually answered, without dominating game-based lessons.
4. Canonical evidence families and required-vs-observed operations follow [Sheets v2 compatibility](../../asit-progress/references/evidence-compatibility.md). A correct chunk order is guided construction, **not** proof of independent written interaction. Every task must state the actual modality and cognitive operation before registration.
5. Developers can run the offline `plugin/scripts/lesson_contract.py` blueprint linter; that script is **not called by ChatGPT skills** and cannot authenticate a current-turn media ref or mobile UI. Verify live sources in the model's tool results, and test host rendering separately.

## Before composing any task

1. Choose observable can-do and time budget, then build an exact task inventory: `task_id | operation | modality | source_or_scene | response_control | answer_provenance`. Use at least **three cognitive operations** in 4–7-minute lessons and **five** in lessons of 20+ minutes. Changed setting or option labels do not count as a changed operation. Never repeat the same operation three times consecutively. Audit the last two displayed lessons; change the dominant operation or modality.
2. **Visual reality check:** for naturally visual topics **first try source-verified real pictures** (with a 16:9 cover if available) and at least two distinct image-dependent operations **only if** suitable source assets were actually retrieved. If not, render a **self-contained SVG diagram scene** with at least two genuinely diagram-grounded operations and a working state-changing control; register modality `visual_symbols` / operation `diagram_*`, NOT `image_choice` or `image_label`. The learner must need the diagram to answer, not just read its alt/caption. Icons, text boards and emojis do not replace a rendered diagram. Never fallback to all-text by default or report photographic evidence without photographs.
3. **Audio decision before task allocation:** for any requested listening and any general English lesson of **15+ minutes**, explicitly check whether short authentic listening helps the chosen can-do. If yes, invoke `asit-media` and validate a real source (original page, working player claim, exact bounded segment/duration, scoped content and comprehension key). In a suitable 20+ minute lesson, reserve one listening section with 2–3 questions when verification succeeds. Place the original source link immediately before those questions. Ask whether the learner actually heard it and whether they read the script; no self-report of hearing means `not_assessed` for listening. No fake Play button or assumed embedding. If verification fails, show `Аудиирование недоступно: источник не подтверждён`; substitute reading **before** preregistration and never silently credit listening. No required audio in a pure writing/reading exercise or a user-requested text-only mode.
4. **Input diversity:** in a 5-task lesson allow at most **two** simple multiple-choice questions; use at least three real response patterns (e.g. picture-word input, sentence construction, decision with consequence, short original answer). In a 20+ minute lesson, at most **35%** of scored tasks may be single-choice recognition; include visual analysis, inference, meaningful manipulation and an original communicative task. Distinct cognitive action matters more than number of controls. Do not add repeated cloze tasks to reach requested duration.
5. **Independent production after skips:** after two skipped original-writing prompts in recent verified turns, replace the large free-response block with a 3–8-word original request or answer **in the first half** of the lesson. Use a *different* communicative situation from any supplied model or assembled sentence. Support by a clear recipient and goal, not by a copyable answer, forced sentence starter or premature correction. Do not count omission as incorrect; don't keep moving the same textarea unchanged.
6. **Meaningful interactivity:** each tap/choice/order control must change visible selected state, sentence, scene state or feedback. For at least one discovery cycle in a visual lesson, the learner predicts a grounded outcome, manipulates a control, then sees feedback. Do not claim drag, picture hotspots, animated physics or live dialogue without working host support. A true multi-turn dialogue spans real chat turns or Voice; a single quiz with speech bubbles is not a dialogue.

## Release check — reject and repair before registration

- Count tasks and duration per current request. 40 minutes cannot be fulfilled by stretching a 7-minute repeated format; divide into **4–6 distinct sections** with different goals and source material.
- Check answer integrity across all visible texts, image labels/alt, chunks, examples and later independent prompts. Correct/Incorrect only after the learner acts; incorrect feedback has no solution hint.
- Check actual asset availability, source attribution, distinct modalities, answer controls, card/all switch, Undo for order, prior input retention, one canonical final Submit, working early-finish confirmation, trusted rubric per task and eventual `not_assessed` for unanswered tasks.
- **Fail = redesign task inventory, not hide requirement.** If a modality cannot run, replace it explicitly, accurately label the replacement, and still provide a full useful lesson. Save-readback and privacy rules remain unchanged.

## Acceptance examples

- **Reject:** 30 tasks = 15 radio choices + 5 cloze + 4 phrase orders + 6 unanswered text boxes, with a decorative cover and no verified listening; the text could be solved without any picture.
- **Accept:** 40-minute scenario with an actual illustrated map/image comparison, verified original-site listening (2–3 questions and hearing confirmation), short reading/inference, stateful word ordering, responsive decision, and brief original communication. Each source/task has independent rubric and correct modality.
- **Reject:** five questions called `image_choice` because icons are visible, or `audio` because a link was put at the end.
- **Accept image fallback:** unavailable photograph -> an **actual self-contained SVG diagram scene**, two distinct grounded visual-symbol questions and a state-changing native control, all appropriately relabelled before Activity preregistration. **Audio fallback:** unavailable audio -> truthful reading exercise without listening credit. A prose-only lesson is not a valid default image fallback.
