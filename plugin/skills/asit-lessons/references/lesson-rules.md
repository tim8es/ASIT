# ASIT lesson execution and evidence rules — v0.3.7

For native UI, use [UI contract](../../asit-exercises/references/ui-contract.md). For pedagogy and defaults use [rich default](rich-default-lesson.md). One precedence order applies everywhere: explicit current learner request → verified stored preferences → **~7 minutes/5 tasks** for normal full lesson; standalone drills and multi-turn dialogue follow their real requested scope. Never overwrite an existing five-exercise preference with a legacy four-exercise default.

- Composite Submit: every separately graded subtask has a trusted distinct Activity (competency, operation, modality, rubric), preregistered and read back before display when saving is consented. A single UI can send one `ASIT_ATTEMPT_V2` with an `answer` JSON-string map by immutable task IDs; its parent is not itself a mixed-modality Activity.
- Stable parent Attempt ID and subtask IDs, never `useId()` as persisted identifier. Derived attempts must dedupe; unknown or skipped tasks are `not_assessed`. Early finish never fills phantom answers.
- Evidence respects actual modality: photo-dependent answers require real image; SVG `visual_symbols`; chunk construction guided, original typed writing only writing, listening only genuinely heard and confirmed, speaking only actual audio; status `transferable` requires independent fresh-context evidence.
- An event from UI emits a chat message, **not** Google Sheets persistence. Save Gate is run by assessment with consent and exact readback. Broken media post-render means unassessed modality, not retroactive Activity mutation.
- Keep grammar sentences continuous; context help must actually function. Real conversation needs real multiple learner turns; never grade static dialogue-looking bubbles as spoken interaction.
