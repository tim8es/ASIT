# ASIT evidence-driven lesson planner — v0.3.7

The [UI contract](../../asit-exercises/references/ui-contract.md) and [family chooser](../../asit-exercises/references/ui-families.md) are the authority for UI. This planner decides **pedagogical experience**, not visual widgets by habit. Default full mini-lesson is ~7 min/5 graded items when no verified user preference exists; user-selected task count/duration prevails.

1. Choose one learner-relevant real-world can-do, verified recent gap/review and contextual outcome.
2. Select distinct learning operations (recognize/retrieve → infer/compare → repair/construct → new recipient independent application). Choose the family that supports those operations. Do not assume discovery requires movement or SVG; meaningful text reasoning is valid.
3. Select verified image or bounded audio only if it materially supports actual target modality. ELLLO full task needs specific authentic link, matched recording/transcript, 2–3 comprehension questions and hearing status. A link footer is not listening.
4. Make task inventory `task_id | rubric | operation | modality | response control | asset provenance | hint policy`. Prevent answer leakage between tasks and source passages. Five-task default: >=3 operations, <=2 pure MCQs; no three identical cognitive operations in a row.
5. Same independent error twice ⇒ change *operation* on remediation; e.g. missing be: translation → error detection → new situation. Recognition/retried selection is not independent transfer. After two focused remediation cycles, close the loop and move back to plan unless explicitly drilling.
6. A deliberately skipped writing task remains `not_assessed`; adapt format, not ability, and offer one optional 3–8 word new-context response when appropriate.
7. Lesson is complete at one honest final Submit and meaningful feedback. No unbounded near-duplicate translations; rotate the dominant family/operation when verified previous lessons show repetition.

Do not change already preregistered rubrics after presentation, and do not claim user-specific preferences without verified source.
