# ASIT independent-answer integrity — v0.3.6

Universal product rule, **not a personal user preference**. The canonical [UI contract](../../asit-exercises/references/ui-contract.md) governs feedback and Submit. Run this check before registering any graded Activity.

1. Finite, unambiguous selected/completed answers receive **provisional** after-action `Correct` or `Incorrect — Try again` (neutral, no directional clue/answer elimination); before learner input reveal nothing. Correct answer may have a short why **only if** no remaining task's answer is exposed. Open natural language or vocabulary synonyms require semantic post-Submit review.
2. Never show the expected answer through headings, prefilled controls, captions, SVG labels, alt, glossary, examples, placeholders, earlier model sentences, initial state or hover. Finite choices may contain correct option but shouldn't telegraph it by length/style/order. Binary yes/no with immediate wrong verdict necessarily permits elimination; prefer 3+ plausible options when independent discrimination matters.
3. Truly independent writing requires changed object/person/situation/recipient and meaningful new information not copyable from a guided sentence or the visible source. Guided word ordering/recognition are *supported*, not independent CEFR production. Factual reading retrieval need not be called independent writing.
4. Preserve first nonblank response and revision markers only if observed by client and mark them unverified; no clipboard interception, claimed anti-cheat monitor, or fake secure first-try guarantee. Local verdict never equals trusted grading/Google Sheets save.
5. For each task, compare every visible piece of source/UI with trusted rubric and modality. If answer leak or ambiguous deterministic key is found, redesign **before** preregistration and readback. If issue surfaced only after presentation, do not silently rewrite the Activity history.
6. Submit may be incomplete after explicit confirmation; unsubmitted parts `not_assessed`. Let `asit-assessment` validate trusted IDs/rubrics and issue truthful save/CEFR status.

Examples: Reject a chunk-built sentence followed by `Write the same sentence` as independent transfer. Accept a new recipient and distinct request with no ready-to-copy response. Reject `Incorrect — choose in` after wrong choice; accept `Incorrect — Try again` after input, final explanation after Submit.
