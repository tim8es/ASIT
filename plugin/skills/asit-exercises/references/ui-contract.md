# ASIT native UI contract — v0.3.6 (single authority)

**Normative for every structured ASIT lesson and standalone interactive trainer.** This is the sole UI assembly and acceptance contract. Other references may provide examples, but cannot override this contract. Educational validity, consent, evidence provenance and Save Gate retain authority within their respective domains. An explicit learner format request and real platform/accessibility limitations override defaults. Read once per UI delivery, not for quick answers, progress lookup or non-UI chat.

## Default quality, not default gimmick

- First choose observable **can-do**, time and current task-count preference, genuine learning operations and modality. Then choose one of the vetted [UI families](ui-families.md). A rich visual/interactive lesson is the default when relevant and supported; **SVG movement is not obligatory** for reading, writing, dialogue or listening. An unrelated image or arbitrary game is a release failure.
- With no valid user preference, a full mini-lesson defaults to **approximately seven minutes and five graded tasks** (not five fixed exercises for all situations). User-set time, count, accessibility and mode supersede defaults; a standalone drill does not inherit a full-lesson quota.
- One cohesive real-world objective; at least three **genuinely distinct cognitive operations** for a default 5-task lesson; <=2 simple multiple choices; no three consecutive equal operations. Prefer a meaningful fresh-context independent application, optional and short after repeated intentional skips. Source media has to be needed for the task, not merely ornamental.
- Structure: concise goal, estimated budget and short strategy; task content with actual answer controls; Cards/All switch for full lessons of 2+ tasks, Cards default; honest completed-count (never fabricated mastery); optional post-Submit vocabulary without answer leakage.

## Native UI invariants

1. One unconditional top-level `{@body ...}` for hooks. Build visible controls from supported `button`, `radio-group`, `select`, `input`, `textarea`, `segmented-control`, `checkbox` and other *real* available primitives. `svg` draws only; click handlers belong on native controls; no inert faux hotspot, Play, Record, drag, countdown, motion, or simulated media.
2. Every visible control has a real callback and a **meaningful observable effect**. Never use unsupported JS APIs inside native UI. An SVG state change is a symbolic diagram change, not a generated photo or animation.
3. All answers and first-try metadata live in shared unconditional state; Cards⇄All, Previous/Next, Undo, Replay and incomplete confirmation do not erase unrelated answers. Reset cannot overwrite an earlier first attempt. If revisions cannot be reliably captured, leave metadata unknown.
4. Deterministic finite answers: nothing correct/incorrect before input; after input, show provisional `Correct` or `Incorrect — Try again` without revealing the key or naming an untried option. A free-text or semantically ambiguous response is `Review after Submit`. First choice/retries are **unverified client claims**, not automatically awarded independent evidence.
5. Each graded task has an independently specified trusted rubric, accepted alternatives, operation, modality and immutable ID before rendering. Use actual source-verified imagery only for image-scored Activities. SVG must be `visual_symbols`; text is not listening/speaking. Broken media means `not_assessed` in that modality. With a consented store, pre-register/readback all Activities before display; otherwise label unsaved.
6. Exactly one logical final Submit (`GenUI.issueNewTurn`), with one immutable parent Attempt ID and JSON-string answer object keyed by registered task IDs. Empty tasks stay omitted/`not_assessed`; optional explicit early finish available on *every* screen. Missing answers trigger local confirmation `X answered / Y skipped`, with `Send X answers` and `Continue lesson`. No fake persistence checkmark. Disable/reject repeated UI submissions to the extent client state permits; trusted server/provider side still must dedupe.
7. Accessibility: native labels, keyboard-operable controls, readable small-screen layout, sufficiently large tap targets, source alternative text that does not disclose keys, static/reduced-motion alternative; never assert successful client rendering without observation.
8. Independent production cannot be solved by copying visible chunks, options, captions, hints or examples. If a control or asset is unavailable, **revise the task + rubric + modality before registration** or mark a post-render failure `not_assessed`; make the fallback actually useful.

## Pre-render gate: FAIL => redesign, not silently omit

`can_do?` / `task_ids+rubrics?` / `family suited?` / `operations diverse?` / `controls supported?` / `state+feedback correct?` / `no premature key?` / `Cards-All preserves state?` / `one real Submit?` / `early exit works?` / `assets evidence-grounded?` / `consent-readback or UNSAVED?`. For symbolic visual tasks require actual task-dependent SVG evidence; for listening require a scoped verified real recording plus hearing-mode self-report. No mandatory photo hunt or unrelated SVG in text-oriented tasks.

Run the deterministic reference test cases and real desktop/mobile acceptance cases when publishing; model self-review **does not prove** host behavior. Treat compiled/testing scripts as developer tooling only: Skills-only plugin files do not execute Python/Node during lessons.
