# ASIT vetted UI families — v0.3.6

Pick **ONE main family** from the learner's can-do and actual modality before making an Activity blueprint. This file defines stable interaction shapes, not a requirement to repeat the same story or to insert a meaningless mini-game. Task count/duration/assistance from user settings override the default. For complete DIL implementation mechanics follow [complete-native-lesson](complete-native-lesson.md) and the mandatory [UI contract](ui-contract.md).

| Family / when | Fixed control pattern | Feedback and evidence | Hard fallback |
| --- | --- | --- | --- |
| **visual_discovery**: spatial relations, object vocabulary, diagram logic | supported source image or `svg`, first `radio-group` prediction, native `button` to change diagram state, `select`/`input` observation, `button` chunk-order with Undo and independent `textarea` | finite selections after attempt, semantic text after Submit; SVG tasks `visual_symbols` only | diagram replaces unverified photo before registration; if SVG unsupported, revise to an honest nonvisual comparison |
| **communication_mission**: messages, polite requests, workplace decisions | continuous situational chat/message in `<text>`, decision `radio-group`/`select`, reversible assignment or consequence via native `button`, contextual correction `input`, fresh recipient `textarea` | decision result only after selection; free language reviewed semantically | no fake live dialogue; call it scenario + writing; real dialogue requires separate turns |
| **reading_reasoning**: reading, grammar inference, text/email analysis | genuine continuous passage, gist finite-choice `radio-group`, detail/reason `input`, sortable event or evidence buttons when meaningful, fresh reply `textarea` | explicit reading/inference modality, textual support stays available | **no compulsory SVG, cover or fake animation**; reading works with text and native controls |
| **listening_lab**: audio/video comprehension | verified source title + original link adjacent, listening-mode confirmation `radio-group`, gist choice, detail `input`, optional short written response | only heard audio without transcript qualifies as provisional listening evidence; reviewed after Submit | unverified duration/playback => relabel to reading or `not_assessed`; no invented player |
| **focused_drill**: explicit short grammar, vocab or one mechanic | one to several uncluttered `radio-group`/`input`/`button` ordering controls, repeated only when explicitly requested | local finite feedback after input, originals after Submit, first-attempt provisional only | valid text fallback; no five-task quota or artificial image |
| **dialogue_voice**: spontaneous multi-turn conversation | real ChatGPT turns/eligible Voice session, one responsive question at a time | speaking only when audible actual speech; typed interactions are text interaction | never fake microphone or grade one textarea as conversation |

## Interoperability and variety

- Shared shell for multi-task families: goal, true `answered/N`, Cards/All, stable state, full answer map, incomplete-submit confirmation and one final Submit. Use shell only when multiple on-screen scored tasks actually exist; real multi-turn dialogue need not be forced into a static form.
- Every native finite control compares **its own exact permitted value domain** with its trusted key. No cross-field comparisons. A game consequence is a scene/assignment state, not an extra invented graded Activity.
- Within a family vary the cognitive actions, communicative stakes, texts and input mechanics. Rotate dominant family/operation after repeated genuine errors and when recent verified lessons show repetition. Never repeat a parcel/mug template solely because it is easiest to render.
- Decorative images and text-only tasks masquerading as image tasks fail. Interaction need not be motion; text selection, sequencing and evidence comparison can be high-quality interactive learning.
- Native UI is built per ChatGPT response from these fixed patterns; there is **no installed executor** that imports and runs this table as code. Enforce deterministic behavior through thoroughly checked exemplar templates and offline tests, not a claim of runtime guarantee.
