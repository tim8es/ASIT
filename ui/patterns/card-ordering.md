# Accessible card ordering
**Use:** assemble meaningful chunks into an utterance or sequence; test order, not motor dexterity.
**Input:** working drag-and-drop *only* if accessible in current client. Always support numbered choices, keyboard reordering or a typed sequence.
**Hints:** clarify which chunk starts/ends, without pre-sorting cards.
**Feedback:** show the correct sequence with a short rationale, then transfer.
**Evidence:** guided construction or ordering recognition, not independent speech.
**Fallback:** learner enters tokens in order (e.g., 3, 1, 4, 2). If functional drag is unavailable, render this fallback directly.
