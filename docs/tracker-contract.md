# Private storage contract v2 (Google Sheets adapter)

New learners use one privately owned Google Sheet named **ASIT — Learner State**. The public repository contains its **empty tab specification**, not learner files. See \`templates/tracker-v2.json\` for exact tab headers.

## New setup

Require storage consent. Find a uniquely identified existing learner workbook or create an empty native Sheet. Do not auto-select among several same-named Sheets. Create nine tabs using exact headers from the template:
\`Config, Goals, Competencies, Plans, Activities, Attempts, Reviews, Sessions, Events\`.

Write \`schema_version = 2\` into Config with JSON value \`2\`. Save learner preferences and goals only after the learner provides or approves them. All dates are actual ISO UTC values when known; otherwise empty. An empty competency row means **unassessed**; do not initialize fake results or B2 assumptions.

### Record mapping

- \`Config\` stores profile settings as key and serialized JSON value. Keep private URLs, permissions and secrets out of the repo and do not needlessly duplicate them in chat.
- \`Goals\` holds editable user intentions.
- \`Competencies\` contains individual, agent-built can-do skills, dependencies, priorities and qualified summaries.
- \`Plans\` retains learning plan revisions with reasons.
- \`Activities\` is the **trusted registry** of prompts and rubrics, stored before accepting a reply from an older chat context.
- \`Attempts\` captures actual evidence. A user may choose \`privacy_mode=summary_only\`; the raw answer is then not stored in Sheets.
- \`Reviews\` is a compact due set, not a synonym for mastery.
- \`Sessions\` summarizes completed sessions with attempt IDs.
- \`Events\` records migrations or human correction and state changes, with minimal metadata.

Keep row positions out of identity; use stable UUID-like IDs generated by the runtime/tool when available. Check for an existing attempt ID before appending, and **always** read back exact match after writing. **Sheets doesn't enforce atomic uniqueness**.

## Backwards compatibility

The v0.1 private pilot workbook contains \`Profile, Skills, Review Queue, Sessions, Attempts\`, and \`Skills!I\` is its skill-ID field. Do not modify, delete or publish this legacy data.

On an existing legacy workbook: (a) read schema and ask before migration, (b) create a backup/copy, (c) create a new clean v2 workbook or new versioned tabs, (d) map only real observed records, (e) verify counts and samples, and (f) switch configuration only after confirmation. Preserve original document references privately. For a one-time pilot lesson, legacy reads can continue with a version-aware adapter until migration.

Legacy mapping: \`skill_id\` → \`competency_id\`; \`learner_answer\` → \`answer_or_summary\`; \`Review Queue\` → \`Reviews\`. A missing legacy timestamp should remain blank. Never elevate old confidence to a scientific mastery score.

## Privacy, correction and export

Do not place real learner IDs or store URLs in Git. Allow view/correction of assessments, data export (JSON/CSV) and deletion of learner-controlled sheets/rows on explicit request. Respect current storage settings and avoid collecting audio/transcripts without a separate explicit opt-in. For a future transactional adapter, preserve these logical entities but change the storage backend only if it provides measurable benefits.
